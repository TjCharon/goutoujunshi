# 狗头军师商业化可行性证据收集方案

> 文档状态：研究方案，尚未实施。
>
> 本文用于收集和核验商业化决策所需证据，不代表已经完成法律、支付、备案、模型供应商或商业可行性验证。

## 一、当前已确认的关键信息

- 暂停全部实施，不修改 APK、后台或支付逻辑，也不调用现有付费模型接口。
- 首版定位为“用户主动点击后分析第三方聊天”的按需工具，不提供虚拟恋人、持续陪伴或主动情感互动。
- 封闭测试仅限 18 岁以上，预计不超过 50 人。
- 当前尚无公司、个体工商户或其他经营主体。
- 因此，当前阶段不能按原计划直接接入企业商户并公开收费；应先确定经营主体路径。
- 使用已备案大模型 API 不代表 APP 自动合规。公开信息显示，直接调用已备案模型的生成式 AI 应用通常仍需向属地网信部门办理登记，并公示模型名称及备案号。参考：[国家网信办备案公告](https://www.cac.gov.cn/2024-04/02/c_1713729983803145.htm)。
- 微信支付 APP 支付支持企业和个体工商户，但官方申请材料要求营业执照，而且 APP 支付权限指引要求提供主流应用市场下载页。仅依靠官网下载 APK 可能无法直接满足该路径，需要进一步书面确认或改用网页支付方案。参考：[微信支付主体权限](https://pay.wechatpay.cn/doc/v3/merchant/4015477838)、[APP 支付申请指引](https://pay.wechatpay.cn/doc/v3/merchant/4013070174)。
- 关系建议工具虽然不必然属于“拟人化互动服务”，但其内容涉及情绪支持、亲密关系和私人聊天，必须取得正式分类意见。严格保持“按需决策工具”定位有助于降低被认定为持续情感互动服务的风险。参考：[拟人化互动服务管理暂行办法](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)。

## 二、证据包内容

### 2.1 经营主体与收费路径

比较三条路线：

| 路线      | 需要核实的证据                           | 暂定判断                |
| ------- | --------------------------------- | ------------------- |
| 有限责任公司  | 注册、经营范围、税务、支付商户、APP/域名备案、责任隔离     | 正式公开经营优先方案          |
| 个体工商户   | 是否可覆盖软件与 AI 服务经营范围、支付能力、责任承担、备案资格 | 可能适合小规模测试，但个人承担风险更高 |
| 无主体免费内测 | 免费测试协议、隐私义务、模型费用由谁承担、不得收费的边界      | 可用于产品验证，不能替代正式商业路径  |

需要从市场监管、工信、属地通信管理局、微信支付和支付宝官方渠道确认：

- 推荐的经营范围。
- 个体工商户能否作为该 APP 的主办者和 AI 服务运营者。
- 经营性互联网信息服务是否需要额外许可，而不仅是 ICP/APP 备案。
- APP 主办者、域名备案主体、支付商户和隐私政策运营者是否必须保持一致。
- 官网侧载能否申请微信、支付宝 APP 支付；如不能，网页收银台、公众号或应用商店上架分别需要什么条件。
- 数字服务退款、发票、税务和消费者权益要求。

输出一张“主体 × 支付 × 分发 × 备案”可行性矩阵。任何未经官方确认的项目明确标为“待主管部门/支付机构书面确认”。

### 2.2 AI 服务监管分类

以实际产品流程制作监管判定材料：

- 用户主动点击分析，不自动与用户持续聊天。
- AI 分析的是用户提供的第三方聊天内容。
- 输出包含关系判断、行动建议和候选回复。
- 不创建虚拟伴侣或长期人格。
- 不面向未成年人。
- 不提供医疗、心理诊断、法律或金融决策。
- 不把用户聊天用于训练。

分别核验：

- 是否属于面向境内公众的生成式 AI 服务。
- 调用已备案模型时，APP 需要办理“应用登记”还是独立算法/模型备案。
- 是否需要公示模型名称、备案号及 AI 生成标识。
- 是否可能被认定为拟人化互动服务。
- “付费封闭测试”是否仍属于向公众提供服务。
- Jev 分类、自动主题识别、候选回复排序是否涉及算法备案。
- 是否需要内容审核、投诉举报、极端情境处置和安全评估机制。

最终取得一份律师或属地主管部门可审阅的产品说明，而不是只拿产品名称口头咨询。

### 2.3 私人聊天与个人信息合规

制作完整数据流图，逐项记录：

```text
微信等聊天界面
→ Android 无障碍服务
→ 本地文字提取和角色识别
→ 你的后台
→ Jev/模型供应商
→ 返回建议
→ 后台删除请求正文
```

对每个环节查明：

- 收集的数据字段、必要性和保存期限。
- 是否包含敏感个人信息。
- 用户是否有权把聊天另一方的信息发送给 AI。
- 是否需要对截图、联系人名称、头像和聊天正文分别取得单独同意。
- 模型供应商是否保存或训练输入内容。
- 数据是否出境；海外 OpenAI 兼容接口是否适合默认开放。
- 无障碍权限的显著说明和撤回方式。
- 用户注销、数据查询、删除、投诉和安全事件处理流程。

默认安全边界保持为：本地 OCR、只上传结构化文字、默认不传截图、后台不持久化正文、日志不记录正文、供应商不得用输入训练。必要个人信息应遵循最小化原则。参考：[移动 APP 必要个人信息规定](https://www.miit.gov.cn/jgsj/xgj/gzdt/art/2021/art_4e535277ab4343ee9010dbbaf90aab64.html)。

### 2.4 模型供应商证据矩阵

针对候选的大陆合规模型和 Jev 分别收集：

- 模型名称和备案号。
- API 商用、转售、代理调用和面向终端用户收费条款。
- 输入数据保存期限及是否默认用于训练。
- 数据中心地区和跨境情况。
- 输入、输出、缓存及推理模式价格。
- 并发限制、可用性承诺、退款政策。
- 内容安全能力和被封禁场景。
- API Key 轮换与子账号权限。
- OpenAI 兼容程度。
- 是否允许关系、情感建议类场景。

不只依据营销页面；商用和数据条款必须来自正式服务协议、隐私文件或供应商书面回复。

### 2.5 公开成本与盈亏模型

不调用真实接口，先建立区间模型：

```text
单次分析成本
= Jev 判断成本
+ 回复生成成本
+ 候选排序成本
+ 重试成本
+ 短信验证码
+ 云服务
+ 支付手续费
+ 退款和异常使用损耗
```

至少计算：

- 每月 20、100、300、1000 次分析四档用户。
- 短、中、长聊天记录三种 Token 长度。
- 正常、重试一次、供应商故障三种场景。
- 10、50、500 个付费用户下的月成本。
- ¥19、¥29、¥39、¥59 四个价格点。
- 目标毛利 70% 时各套餐可包含的分析次数。
- 单账号两台设备、账号共享及自动化滥用后的最坏成本。

费用数据只引用供应商官方定价，并记录查询日期。最终输出可修改参数的成本计算表，暂不确定正式售价。

## 四、Go/No-Go 门槛

只有同时满足以下条件，才进入实施阶段：

- 确定有限公司或个体工商户路线，并完成主体注册。
- 支付机构书面确认所选分发方式可接入相应支付产品。
- 明确 APP、ICP 和生成式 AI 应用登记路径。
- 确认所用模型已备案并允许商业代理使用。
- 确认严格按需工具是否落入拟人化互动服务规则。
- 确认聊天数据处理、无障碍权限和第三方信息处理方式可以合法实施。
- 公开成本模型证明套餐在保守使用情形下仍能达到目标毛利。
- 对仍无法确认的问题取得专业法律意见。

在这些证据完成前，仅允许自用或不收费、受邀请的产品验证；不公开销售、不宣传“无限使用”，也不向 APK 内写入生产 API Key。

## 五、明确不在本阶段实施的内容

- 不搭建后台服务。
- 不接入支付。
- 不修改 APK 或 Android 源代码。
- 不迁移或隐藏当前 API 配置。
- 不创建正式签名或发布渠道。
- 不调用真实模型进行成本基准测试。
- 不对外发布、收费或招募测试用户。
